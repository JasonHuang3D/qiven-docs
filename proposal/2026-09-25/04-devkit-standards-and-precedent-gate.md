## 1. What the existing law says and what it proves

The [engineering philosophy](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/collaboration/software-engineering-philosophy.md) §1–3, §5, §9 and [Memory Constitution](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/MEMORY-CONSTITUTION.md) §8, §15, §17 already reject local-first apprenticeship, unfinished foundational holes and the idea that passing validation proves a mature design. [ADR-0024](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/decisions/ADR-0024.md) outranks superseded ADR-0007 on placement. [ADR-0044](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/decisions/ADR-0044.md) makes one session responsible for its own exact-delta review; it also explicitly says to strengthen gates or restore independent review if that discipline misses a defect class. [ADR-0046](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/decisions/ADR-0046.md) places the shared engineering standards in Devkit. [ADR-0050](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/decisions/ADR-0050.md) accepts deterministic task activation, independent falsification for R2/R3 and scar embodiment. The [accepted cognitive governance program](https://github.com/JasonHuang3D/qiven-docs/blob/main/accepted/2026-09-23/00-qiven-cognitive-governance-program.md) CG-5/6/7/8 already says that repeated incidents require controls, correlated author tests are insufficient and a derived summary cannot be promoted to canonical truth.

These are real decisions: an accepted ADR remains binding within its scope until formally amended or superseded. Owner acceptance establishes that governance authority; it does **not** prove that an old implementation remains correct under a new dependency, platform, harness, threat model or acceptance target. Under this program's epistemic stance (owner direction 2026-09-26), every prior decision is simultaneously a fallible record: when incident evidence or memory contradicts a governing ADR, the evidence wins the review position and the contradiction goes to owner adjudication. If new evidence contradicts the governing ADR, stop for canonical adjudication rather than quietly ignoring it. Likewise an existing source file is evidence of past behavior, not a specification. A previous `PASS` proves only the properties actually exercised at that exact source/configuration. The rule must be enforced at the point where an agent selects an old example as a template, at the defect repair boundary, and at candidate publication. More copies of the same admonition increase reading noise without changing that outcome.

## 3. Proposed normative change: old code is a hypothesis, never its own oracle

The following adds **operational acceptance criteria** to existing ADR-0024/0044/0050 and Devkit standards; it does not create another general engineering philosophy. Apply it at a task boundary for R2/R3, at any repeated scar, and when a bug fix crosses an external, ownership, authority, filesystem or protocol boundary. Ordinary R1 under a stable accepted contract keeps its existing proportional scope.

**PR-1 — Revalidate every borrowed premise.** An accepted ADR supplies binding authority within its current scope; a prior PR, earlier local implementation, passing gate or stable-looking API supplies a candidate and provenance, never its own correctness proof. Before copying its semantics, identify: (a) the present governing source and supersession status, (b) the real consumer and exact current version, (c) assumptions borrowed from previous code, (d) observable counterexample that would falsify each material assumption, and (e) the independent oracle: accepted contract with directly applicable preconditions, vendor/harness behavior, platform API contract, actual boundary trace, or qualified independent test. A result derived from the same code under review is **not** an independent oracle. A prior owner acceptance supplies authority for a decision at its time, not timeless empirical verification.

**PR-2 — Stop patch-to-green when the mechanism is not understood.** For a regression or owner-live failure, reconstruct the end-to-end causal sequence from the external input to the observable result and enumerate which boundary invariant failed. A subsequent fix to the same hazard may not proceed as a local literal change if the earlier repair did not explain or test the violated contract. If a test, CI run or H1 contradicts an author assumption, change the task's risk and design state before another semantics-bearing patch; do not silently re-run until green. Where the real contract is unknown, create a bounded disposable probe with an explicit falsifier and capture its result before fixing production behavior.

**PR-3 — Demonstrate discriminating proof.** A defect correction names a regression that fails on the **pre-fix** behavior and passes on the candidate, plus a negative or near-miss that exposes an attractive incorrect fix. When reproducing the old code is infeasible, record a concrete alternative falsification method and its limits; “100 green tests” with the same self-authored assumption does not meet this rule. For a two-frame hello+event deadline, a one-frame echo is insufficient. For a path identity rule, string lexical agreement is insufficient for a filesystem authorization claim. For a borrowed span, happy-path parsing without lifetime stress is insufficient. Record the exact candidate, platform, harness and configuration that ran.

**PR-4 — Independence follows risk, not role names.** Apply ADR-0050/CG-6 as accepted: R2 needs independent falsification of material assumptions; R3 and production trust boundaries need the stronger orchestrated isolation and owner handoffs where required. A different agent reading the same stale authority pack and only repeating author tests is not independent evidence. A fresh reviewer receives the task contract, canonical source closure, external oracle and exact diff, with a mandate to break the candidate. It must be possible to return a concrete counterexample or “unproven”; review text alone does not grant a PASS.

**PR-5 — Acceptance state is typed.** Distinguish `AUTHORITY_ACCEPTED` (owner accepted a decision), `CONTRACT_VERIFIED` (current consumer and environment match its preconditions), `REGRESSION_PROVEN` (old behavior fails and candidate passes), `INTEGRATION_PROVEN` (actual boundary run at pinned versions), and `UNPROVEN`/`SUPERSEDED`. These are claim scopes, not invented replacements for Context's H1–H4. A standard's “normative” label may determine intended behavior but cannot substitute for a missing detector. Record uncovered scope and expiry; do not store an untested inference as “verified”.

## 4. How to make the rule mechanically useful

Use the accepted [TCA/CA-2 path](https://github.com/JasonHuang3D/qiven-context/blob/c73b2288bb1dabfa87a5c222eeab0d7bae6ac2ff/decisions/ADR-0050.md) for task-time selection and evidence receipts, not a second retrieval system or the sealed Python ContextKernel. This proposal specifies the missing engineering evidence and stale-document checks CA-2/Devkit must enforce. Until CA-2 actually runs, apply the same checks as a bounded, explicit R2/R3 publication checklist with an independent falsifier; mark it manual, and block the specific unproven boundary rather than claiming a gate already exists.

| Check | Mechanically testable part | Semantic part and honest limit |
| --- | --- | --- |
| **Authority freshness** | At the declared candidate, resolve active pointer/index targets and statuses against pinned repository heads; reject an active normative pointer to a museum/superseded ADR, missing file, obsolete script, conflicting latest accepted topology, or unbound mutable “current SHA.” Maintain a small allowlisted historical-reference class with explicit labels. | A checker cannot decide every partial ADR supersession: an owner-accepted amendment defines scope; conflicts unresolved by the index remain an explicit review stop. |
| **Design-before-code** | For R2/R3, require a source-controlled design artifact with digest and a commit *preceding* the first semantics-changing source commit (or a separately accepted design PR). Bind task scope and activation receipt to that artifact; invalidate material scope changes. A self-authored review note or timestamp is insufficient. This tightens the current same-batch rule and therefore requires explicit owner adjudication before enforcement; existing work is not retroactively called invalid. | Commit order is a necessary trace, not proof the design was intellectually independent or correct. Review tests its assumptions against external truth. |
| **Evidence tuple** | Require a task/PR record with repository heads, risk, boundary, current authority IDs, previous-code assumption, independent-oracle reference, failing-old-case ID, negative-case ID, candidate gate receipts and residuals. The [three-repository audit](05-retire-host-dcr-and-native-doc-authority.md) adds the distinction between a locked graph's tested SHAs and a repository's current candidate head, plus explicit skipped-platform claims. Reject missing/stale references at R2/R3 publication; bind the receipt to **the same cross-repository candidate**. | A filled form can lie. Independent reviewer or real boundary run confirms whether the oracle and tests actually distinguish the defect. The check should avoid requiring irrelevant fields for ordinary R1. |
| **Regression discrimination** | Run the named test on the previous defective revision or a controlled fault injection when feasible, then on the candidate. Require the former to fail for the intended reason and the latter to pass, plus the identified near-miss. Keep deterministic fixtures instead of rerunning a flaky suite until it passes. | Mutation tests demonstrate detector sensitivity to one defect; they cannot prove the full specification or an inaccessible owner environment. Escalate that limit to the actual H1/H2 boundary. |
| **Gate coverage and cost** | Add a fast Devkit source/entrypoint validator and evidence-schema validation to the existing Operator gate; CA-2 supplies activation and falsification receipt checks only when delivered and accepted. Budget check cost, test false positives with permitted historical quotes and legitimate no-design E-cases, and publish measured runtime. | Do not restore the ~300-second write-coupled Context compiler. A passing structural gate proves pointers/ordering/receipts, never that a high-risk implementation is semantically right. |

There must be a visible distinction between **current** policy and **planned** enforcement. A rule whose detector is not shipped has a named human reviewer and a specific claim it cannot yet certify. After CA-2 is proven, remove the interim checklist and duplicate prose; leave a compact pointer to its mechanical check and current contract.

## 6. Acceptance cases and sequencing

1. **Owner adjudicates the delta** to ADR-0044/0046/0050 and design-first timing; preserve the accepted separation of implementation and independent falsification. Do not claim this qiven-docs proposal already overrides them. Select one current rule body in Devkit and Context ADR authority pointers, with no independent competing prose.
2. **Document migration passes real consistency fixtures:** a fake active citation of superseded ADR-0007 fails; a historical citation in `legacy/` with an explicit superseded label passes; a Foundation/Devkit command to absent `tools\format.cmd` fails; a live “Workspace does not exist” entry fails against the pinned Workspace revision; a CA-0 draft presented as a CA-2 gate fails; the legitimate migration-stage `cross-repo-cmake.md` remains marked limited. Bind these checks to the exact document candidate, not to a later main.
3. **Proof mechanism passes adversarial fixtures:** design committed after source with a backdated self-review fails R2 ordering; a missing/changed evidence digest fails; an old defective implementation that passes the new “regression” fails discrimination; a genuine independently sourced boundary oracle plus old-fail/new-pass case succeeds; an allowed R1 test-only or docs-only change is not forced through a design bureaucracy.
4. **Pilot on the concrete H1 scars and Foundation gaps** using published exact source pairs: borrowed-span lifetime; hello+event deadline and registration; path lexical versus OS-backed identity; owning ByteBuilder versus non-owning ByteWriter. Map each to the correct owner and independent oracle. A green author-only unit run cannot close an unexercised real Desktop or Windows filesystem claim. Keep MVP-5/CA sequencing from ADR-0050 until its owner accepts a new order.
5. **Accept only evidenced controls.** Attach gate runtime, false-positive cases, affected repo heads, tests, independent falsification and any unresolved H1 scope. Make the live Devkit standard entry concise after enforcement; remove duplicate prompts that no longer carry a unique selector or action. If a repeated scar still reaches owner H1 while “protected,” classify whether selection, precedence, API, oracle, tests or bypass failed and revise that control before resuming the same repair pattern.

This proposal does not pretend that writing another rule can make a model immune to its own attention bias. The target is a smaller active authority surface, a required external oracle for material borrowed premises, a regression that detects the old error, and publication gates that can refuse unsupported claims.
