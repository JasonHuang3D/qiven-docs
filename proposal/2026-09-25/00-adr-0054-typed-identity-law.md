# ADR-0054 (draft): Make Path and IPC Boundary Contracts Single-Owned

> Status: PROPOSED for owner adjudication and later canonical landing in `qiven-context`. This deliberation copy creates no authority by itself.
> Companion: [ADR-0055 draft](01-adr-0055-simulated-loop-acceptance.md), [incident/evidence audit](02-h1-trial-history-and-defect-evidence.md), [Foundation architecture/museum audit](03-foundation-architecture-and-museum-transition.md), [Devkit standards/precedent audit](04-devkit-standards-and-precedent-gate.md), and [Host/DCR retirement audit](05-retire-host-dcr-and-native-doc-authority.md).

## 1. Existing law and the actual decision

The phrase "land locally first, extract later" was already rejected by [ADR-0024](https://github.com/JasonHuang3D/qiven-context/blob/main/decisions/ADR-0024.md) on 2026-09-15; it superseded [ADR-0007](https://github.com/JasonHuang3D/qiven-context/blob/main/decisions/ADR-0007.md)'s multiple-consumer placement threshold. The [software-engineering philosophy](https://github.com/JasonHuang3D/qiven-context/blob/main/collaboration/software-engineering-philosophy.md) §9 and [constitution](https://github.com/JasonHuang3D/qiven-context/blob/main/MEMORY-CONSTITUTION.md) §15, §17 already reject known-bad first implementations and unfalsifiable deferral. This ADR does not newly revoke those accepted decisions. Under this program's epistemic stance (owner direction 2026-09-26: prior decisions are fallible records; the incident evidence in `evidence/audits/` and `memory/records/` plus current owner rulings are the proof base), those citations are consistency notes, not the justification — the justification is the four-trial evidence and the owner's root-cure direction against the "implement locally first, extract when more consumers appear" principle. It proposes a **specific, enforceable implementation** for two observed boundaries: filesystem path interpretation and the MVP-4 two-frame IPC deadline. A slogan is not a substitute for an owner, a contract, and a regression.

Acceptance of this ADR means: complete the narrow lower-owner primitives and their actual Runtime consumers before *new dependent Runtime semantics*; keep unrelated infrastructure work independently schedulable. The [Foundation audit](03-foundation-architecture-and-museum-transition.md) identifies live bootstrap admission wording and stale authority pointers that must be replaced at canonical landing. “Low-level” cannot function as a ban on stable, product-independent owning compositions earned by a real consumer. This does not require speculative completion of a generic Foundation library or typing every scalar in every repository.

## 2. Failure classification

The [trial-4 audit](https://github.com/JasonHuang3D/qiven-context/blob/main/evidence/audits/2026-09-26-mvp4-h1-trial4-deadline-incident.md) identifies a 9750 ms `session_start` budget copied into both an event and its preceding hello. The host caps hello at 5000 ms and permits 10000 ms for the event. A stronger integer type alone would still permit this exact error: the **frame policy and allocation of one hook's elapsed time** are the missing contract. Paths have a different shape: raw representations are compared in several places with incompatible meanings. The [evidence audit](02-h1-trial-history-and-defect-evidence.md) separates demonstrated bugs, latent risks, and adjacent incidents. These are related engineering symptoms, not proof that one universal "identity" abstraction solves all of them.

## 3. Proposed contract

**BC-1 — Inventory before design.** Record each path-producing and path-consuming boundary used by MVP-4 and the next dependent slice, with source location, trust level, accepted input forms, operation (`display`, lexical comparison, scope authorization, client-image admission, configuration lookup), and exact owner. The initial required inventory is `src/host/runtime_host.cpp::normalize_hook_path` and its governed-scope consumers, `src/scope.cpp`, `src/ipc/named_pipe_server.cpp::ClientRecord::image_allowed`, the ZCode hook payload/argument boundary, profile parsing, and the packaged kit's profile resolution. A CWD-derived absent file is classified as a packaging/entrypoint contract failure; a path value type alone is not its correction. Future sites enter this inventory when touched or when evidence identifies another boundary; do not sweep unrelated display strings mechanically.

**BC-2 — Path representations have distinct claims.** Introduce a narrow `qiven::fs::Path` value type in Foundation for validated *lexical path syntax* with explicit construction, encoding conversion and platform-form handling, when its first concrete Runtime consumer is implemented in the same integration wave. The design must respect Foundation's portable CI, explicit failure and dependency laws. No implicit conversion from raw text; construction returns a typed failure for ambiguous input. The public contract distinguishes absolute/relative and rooted/drive-relative, rejects or explicitly handles malformed and device/UNC forms, and names the base used to resolve relative paths. Windows API image paths must retain a lossless wide-string route; locale-dependent byte case-folding is not an identity rule. MSYS `/d/...` is a *harness/shell input convention* resolved at the ZCode adapter with an explicit, tested drive-mapping policy; it is not an intrinsic filesystem interpretation imposed on every Foundation consumer. The representation choice (`std::filesystem::path` versus an owned encoding) is decided against concrete conversion tests before the public API freezes.

**BC-3 — Lexical equivalence is not filesystem authority.** `Path` may normalize separators/components according to a documented *lexical* contract. It MUST NOT promise that equal-looking strings name the same file, or that `is_under` proves authorized containment: case-sensitive Windows directories, UNC/device namespaces, short names, symlinks, junctions, reparse points, and races can defeat such a claim. Runtime owns a separate scope/admission policy that uses OS-backed identity or a suitably conservative rejection for unresolved targets. For mutations, open/verify the relevant root and target or parent handles, reject forbidden indirection, and bind the check to the effect boundary; match the existing [production MVP architecture](https://github.com/JasonHuang3D/qiven-runtime/blob/main/docs/architecture/runtime-production-mvp-architecture.md) §12.3 (normalize, open, verify the resulting handle stays inside the authorized root; reject junction/symlink/reparse traversal). A PreToolUse hook cannot atomically bind a later arbitrary Bash/Write/Edit effect, so any complete-mediation claim stays limited to the actually proven tool/action/scope tuple. Conservative Bash text detection remains a *separate command-reference heuristic*, never a filesystem identity operation. Unknown or ambiguous classifications must not silently become `not_governed`.

**BC-4 — One IPC deadline contract, applied to each frame and the whole transaction.** The Runtime IPC owner defines the typed budget unit, allowable ceiling by frame kind and event subtype, and the **single monotonic end-to-end hook deadline**. Both encoder/allocation and decoder/validation consume that contract. A `session_start` event may receive an event-grade allowance; its hello must independently obey hello policy, and hello plus event, transport waits and safety margin must fit within the actual harness hook timeout. The corrective design must choose the intended hello/event budgets explicitly; merely widening the host's hello ceiling or capping one literal is not accepted without proving the end-to-end bound. Add encode/decode and real-pipe tests for a refresh-grade event preceded by hello, and timeout/remaining-budget tests. Other wire scalars are typed when a concrete boundary contract needs them; this ADR does not create a global scalar-policy framework.

**BC-5 — Prevention and migration.** Replace each **inventoried security- or correctness-relevant** ad hoc path comparison/normalizer with the appropriate typed parser, Runtime policy, or packaging fix. For each migrated site, show a regression that fails on the prior implementation and a negative test for an alias/ambiguity the primitive cannot safely resolve. Use API boundaries and focused static analysis for known dangerous patterns; an audited gate may flag reintroduced path-prefix checks at named authorization sites, with a documented allowlist for display, wire encoding, and deliberate conservative text detection. A text scan is not proof that arbitrary C++ raw-string path handling is "unconstructible"; report measured coverage and escapes honestly.

**BC-6 — Sequencing and proof.** The owner of this wave publishes the inventory and the concrete Foundation API/Runtime consumer contracts first; reconciles the active Foundation admission/authority pointers as in the [architecture audit](03-foundation-architecture-and-museum-transition.md); implements and tests the lower primitive with its real consumer; migrates the named MVP-4 sites; fixes the IPC transaction contract; then runs the exact-head Foundation and Runtime gates plus ADR-0055's adversarial scenarios. Dependent Runtime semantics do not proceed past an unproven boundary. Workspace resolution/toolchain migrations under [ADR-0052](https://github.com/JasonHuang3D/qiven-context/blob/main/decisions/ADR-0052.md) can proceed on their independent gates. [ADR-0050](https://github.com/JasonHuang3D/qiven-context/blob/main/decisions/ADR-0050.md)'s RR-0 and CA ordering retain their own evidence and acceptance; this ADR must not silently redefine them.

**BC-7 — Tooling-language scope.** The Python devkit operator is *not* protected by a C++ type. Record separately the Python path sites that affect the same kit/identity boundary, assign an owner and a bounded follow-up with a trigger before the next affected packaged acceptance. Use `pathlib` and explicit input-form conversion where appropriate; do not claim a native gate covers Python. An accepted, scoped exception needs its own failure signal and expiry.

## 4. Acceptance evidence and amendment footprint

The canonical landing should update the affected Runtime and Foundation design/contracts, apply the [Devkit precedent/independent-oracle gate proposal](04-devkit-standards-and-precedent-gate.md) after owner adjudication, enumerate exact source SHAs and migrated sites, attach platform cases (Windows with real filesystem alias/reparse probes; Foundation's portable CI), and bind test receipts to the same candidate. Keep a residual ledger for intentionally unsupported input forms, security races and downstream consumers. If a candidate cannot distinguish lexical normalization from authorized object identity, the path wave is not accepted.

This ADR refines enforcement of ADR-0024 and the engineering philosophy. The existing Foundation architecture preserves useful product-free, dependency, ownership, cost and portability constraints, but its original admission wording and obsolete linked documents require the [explicit museum/replacement transaction](03-foundation-architecture-and-museum-transition.md). On owner acceptance, amend the live Foundation entry points and Context roadmap/obligations that conflict with these contracts; do not leave a new ADR beside contradictory live instructions.

## 5. Alternatives and falsifiers

A documentation-only request to "be more careful" does not close the observed recurrence. A Foundation-wide path framework, automatic Unicode case-folding for all Windows paths, a blanket native-string ban, and an all-scalars policy framework are also not justified by this evidence. Falsify this decision if the explicit Foundation path value cannot be portable without higher-layer policy, if OS-backed membership cannot be enforced in the claimed hook boundary, or if the proposed gate produces unacceptable false positives; return those facts to owner adjudication with a narrower scope or revised mediation claim, rather than silently declaring the wave complete.
